## Long summary

Per default, a Monkhorst-Pack[^Monkhorst1976] mesh and a default path is generated. There are default paths tabulated for (nearly) all Bravais lattices. There is no particular logic or reason behind the choice of the tabulated paths, only a vague sense that they produce pleasant plots. It is easy to change the path.

There are three types of meshes implemented, Monkhorst-Pack, FFT and wedge-based meshes. The first two are unremarkable, just regular meshes with the nodes, in fractional coordinates, given by

$$
    q^\alpha_i = \frac{2i-N_\alpha-1}{2N_\alpha}
$$

in the Monkhorst-Pack case, where $\alpha$ is a direction and $N_\alpha$ the density in that direction. In the FFT case it is given as

$$
    q^\alpha_i = \frac{i-1}{N_\alpha}
$$

The wedge-based meshes are not that common and require some explanation.

##### Wedge-based meshes

A general problem with integrations over the Brillouin zone is that we are integrating over a volume that looks something like this:

<center>
<img src="../media/example_bz_genkpoints.png" width="500" />
</center>

This particular example is for Bi<sub>2</sub>Te<sub>3</sub>. Finding a regular mesh that is compatible with the shape of the domain can be awkward. My approach takes a step back, and starts from the basics. The Brillouin zone is a polyhedron in reciprocal space, a volume. The irreducible wedge is the "slice of cake" you end up with once all the symmetries of the lattice are taken into consideration, also a convex polyhedron — the red part in the figure above.

The conventional scheme for symmetry considerations of k-point meshes is to generate a set of points, and then use the symmetry operations of the lattice to figure out which point is equal to which point under which operation, as such building up weights for the points. The wedge-based meshes work backwards. The starting point is the polyhedron defined via the irreducible wedge. This wedge is then sliced into tetrahedrons:

<center>
<img src="../media/example_wedge_genkpoints.png" width="600" />
</center>

This division is done via a weighted Delaunay tetrahedralization, courtesy of [CGAL](http://www.cgal.org). This mesh can the be further optimized with a global optimization scheme to ensure tetrahedrons that are as even as possible, and as close to regular tetrahedrons as possible.

Once the tesselation of the irreducible wedge is determined the full mesh is generated by applying the symmetry operations to the irreducible wedge. The end result is a mesh that is absolutely symmetry compliant, both the points and the tetrahedrons.

### Output files

The path is per default written to `outfile.qpoints_dispersion` (format defined [here](../page/files.html#infile.qpoints_dispersion)) and looks like this:

```
CUSTOM
        100 # number of points on each path
          4 # number of paths
 0.0000000000000  0.0000000000000  0.0000000000000   -0.5000000000000 -0.5000000000000  0.0000000000000  GM    X
-0.5000000000000 -0.5000000000000  0.0000000000000   -0.6250000000000 -0.6250000000000 -0.2500000000000  X     U
-0.3750000000000 -0.7500000000000 -0.3750000000000    0.0000000000000  0.0000000000000  0.0000000000000  K    GM
 0.0000000000000  0.0000000000000  0.0000000000000   -0.5000000000000 -0.5000000000000 -0.5000000000000  GM    L

# below are all available high-symmetry points.
#  0.0000000000000  0.0000000000000  0.0000000000000  GM
#  0.5000000000000  0.5000000000000  0.5000000000000  L
#  0.3750000000000  0.3750000000000  0.7500000000000  K
#  0.2500000000000  0.5000000000000  0.7500000000000  W
#  0.2500000000000  0.6250000000000  0.6250000000000  U
#  0.0000000000000  0.5000000000000  0.5000000000000  X
```

The commented lines at the end are all the possible high-symmetry points (in fractional coordinates), in case you want to modify the path.

The mesh is written to `outfile.qgrid.hdf5`. This is not meant to be human readable, although the file format is not too complicated. Most of the codes accepts the option `--readqmesh` to use pre-generated meshes.
